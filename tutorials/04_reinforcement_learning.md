# Tutorial 4: Reinforcement Learning

Reinforcement learning (RL) fine-tunes a pretrained generative model to produce molecules
that score highly on one or more user-defined property criteria, while staying close to the
original model's distribution.

GraphINVENT2 uses the **augmented log-likelihood** (AugLog) objective from REINVENT
(Olivecrona et al. 2017; Blaschke et al. 2020; Atance et al. 2021):

```
loss = ( log p_agent(x) - log p_prior(x) - σ · score(x) )²
```

where:
- `p_agent` is the model being optimised (updated every step)
- `p_prior` is the frozen pretrained model (fixed)
- `score(x)` is the scalar reward for molecule `x` (between 0 and 1)
- `σ` (sigma) controls how strongly the reward pulls the agent away from the prior

A **best-agent-so-far (BASF)** replay buffer is also maintained.  Molecules generated by
the best-performing agent seen so far contribute to the loss with weight `α`.

1. A **pretrained model** from [Tutorial 2: Pretraining](./02_pretraining.md) or

## Scoring functions

Each generated molecule receives a score between 0 and 1 from one or more **score
components**.  The score components available are:

| Component | Description |
|-----------|-------------|
| `"QED"` | Quantitative Estimate of Drug-likeness (0–1; RDKit) |
| `"target_size=N"` | Reward for generating molecules with exactly N atoms; score = 1 − |n_nodes − N| / (max_n_nodes − N).  Note: N must be strictly less than `max_n_nodes`. |
| `"<name>_activity"` | Predicted probability of activity from a pretrained QSAR model, where `<name>` must match a key in `qsar_models` |

### Combining score components

| `score_type` | Behaviour |
|-------------|-----------|
| `"binary"` | Molecule scores 1 iff **all** components exceed their `score_thresholds`; 0 otherwise |
| `"continuous"` | Final score = **product** of all component scores (thresholds ignored) |

When only one component is listed in `score_components`, `score_type` is ignored.

### QSAR models

For activity-based scoring, you need a pre-trained scikit-learn classifier saved as a
pickle file.  The classifier must implement `predict_proba` and expect a 2048-bit ECFP4
fingerprint as input.

```python
# Example: training a simple SVM classifier and saving it
from sklearn.svm import SVC
import pickle

clf = SVC(probability=True)
# ... fit clf on labelled fingerprints ...

model_dict = {"classifier_sv": clf}
with open("data/surrogates/my_qsar_model.pickle", "wb") as f:
    pickle.dump(model_dict, f)
```

The `qsar_models` dict maps the component name (as used in `score_components`) to the
path of the corresponding pickle file:

```json
"score_components": ["QED", "drd2_activity"],
"score_thresholds": [0.5, 0.5],
"qsar_models": {"drd2_activity": "data/surrogates/my_qsar_model.pickle"}
```

The path is resolved relative to the working directory where `submit.py` is executed.

> **Note:** The repository ships with an empty placeholder at
> `data/surrogates/QSAR_model_example.pickle` (0 bytes).  Loading it will raise
> `EOFError`.  Replace it with a real trained model, or set `"qsar_models": {}` and
> remove any `"*_activity"` entries from `score_components` if you don't need
> activity-based scoring.

## RL-specific parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `pretrained_model_path` | — | Direct path to the `.pth` checkpoint to load (e.g. `"./output/debug/pretrain/job/model_restart_100.pth"`).  Model architecture is loaded automatically from `params_all.json` in the same directory. |
| `score_components` | `["QED"]` | List of scoring components |
| `score_thresholds` | `[0.5]` | Per-component threshold for binary scoring |
| `score_type` | `"binary"` | `"binary"` or `"continuous"` |
| `qsar_models` | `{}` | Dict mapping component names to QSAR model paths |
| `sigma` | `20` | Score–likelihood coupling strength.  Larger values focus the agent more tightly on high-scoring molecules but risk mode collapse. |
| `alpha` | `0.5` | BASF weight in the loss (0 = agent only, 1 = BASF only) |
| `epochs` | `100` | Number of RL steps |
| `batch_size` | `50` | Number of molecules generated per RL step.  Smaller than pretraining because each molecule is fully generated and scored. |
| `accumulation_steps` | `1` | Number of RL steps whose gradients are accumulated before each optimizer update.  `1` means one optimizer update per RL step (standard).  Increase to effectively enlarge the molecule batch per update. |
| `sample_every` | `10` | Evaluate the agent every N steps |
| `n_samples` | `100` | Molecules generated during evaluation |

### Choosing `sigma`

`sigma` balances exploration vs exploitation:

| Situation | Recommended `sigma` |
|-----------|---------------------|
| Wide exploration, gentle push | 5–10 |
| Standard fine-tuning | 20 |
| Aggressive optimisation, risk of mode collapse | 50–100 |

Start with `sigma = 20`.  If the agent collapses (fraction_valid drops, all molecules look
the same), reduce `sigma`.  If the agent barely moves from the prior after many steps,
increase `sigma`.

## Configuration file

> **Tip:** `jobs/rl/params.json` is a template — copy it before editing
> so the original stays intact and each experiment has its own config file:
> ```bash
> cp jobs/rl/params.json jobs/rl/my_experiment.json
> python submit.py --config jobs/rl/my_experiment.json
> ```

Edit your copy of `jobs/rl/params.json`:

```json
{
  "submission": {
    "python_path": "python",
    "graphinvent_path": "./graphinvent/",
    "data_path": "./data/datasets/",
    "job_name": "run",
    "use_slurm": false,
    "slurm": {
      "account": "XXXXXXXXXX",
      "run_time": "0-12:00:00",
      "gpus_per_node": "T4:1"
    }
  },
  "job": {
    "job_type": "rl",
    "device": "cuda",
    "batch_size": 50,
    "accumulation_steps": 1,
    "epochs": 100,
    "init_lr": 1e-4,
    "max_rel_lr": 10,
    "min_rel_lr": 0.0001,
    "sample_every": 10,
    "n_samples": 100,
    "n_workers": 0,
    "restart": false,
    "pretrained_model_path": "./output/pretrain/job/model_restart_100.pth",
    "score_components": ["QED", "target_size=12"],
    "score_thresholds": [0.5, 0.0],
    "score_type": "binary",
    "qsar_models": {},
    "sigma": 20,
    "alpha": 0.5,
    "use_tensorboard": true
  }
}
```

> **`dataset` is optional** for RL jobs that specify `pretrained_model_path`.
> When omitted, the dataset directory is inferred automatically from the pretrained
> model's `params_all.json`.  Set `dataset` explicitly in the `submission` block only if
> you want to evaluate UC-JSD against a different dataset than the one used for pretraining.

> **Model architecture** (`enn_depth`, `hidden_node_features`, etc.) is loaded
> automatically from `params_all.json` in the same directory as the `.pth` file.
> You do not need to repeat these in your RL config.

> **`target_size=N`** requires N strictly less than `max_n_nodes` (the denominator in the
> scoring formula becomes zero otherwise).  Setting `score_threshold = 0.0` means any
> molecule passes regardless of its actual size; raise it (e.g. `0.8`) to demand molecules
> that are close to the target.

## Output files

Output is written to `output/<dataset>/rl/job_0/`.

| File | Description |
|------|-------------|
| `params_all.json` | All resolved parameters |
| `score.log` | Per-step average score (most important RL metric) |
| `convergence.log` | Per-step LR, training loss, mean score |
| `generation.log` | Per-step molecule quality metrics (validity, uniqueness, etc.) |
| `model_restart_<step>.pth` | Model checkpoint saved after each evaluation step |
| `generation/` | Generated SMILES and likelihoods for each evaluation step |

## Monitoring RL progress

### `score.log`

```
Step, Score
Step 0, 0.05000000
Step 10, 0.12345678
Step 20, 0.23456789
...
```

The score should increase over steps as the agent learns to generate molecules that satisfy
the scoring criteria.

### `generation.log`

Watch `fraction_valid` and `fraction_valid_pt` — if they drop sharply, the agent may be
collapsing.  Also watch `avg_n_nodes` to see if the agent is converging to the target size.

### TensorBoard

```bash
tensorboard --logdir output/<dataset>/rl/<job_name>/tensorboard/
```

Tracks agent log-likelihood, prior log-likelihood, training loss, and evaluation score.

## Defining a custom scoring function

To add a new score component, edit `graphinvent/ScoringFunction.py`.  Add a new branch
to the `get_contributions_to_score` method:

```python
elif score_component == "my_property":
    scores = torch.tensor(
        [compute_my_property(graph.molecule) for graph in graphs],
        device=self.device
    )
    contributions_to_score.append(scores)
```

Then add `"my_property"` to `score_components` in `params.json` (and a threshold in
`score_thresholds`).
